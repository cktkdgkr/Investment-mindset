# Orchestrator

집필 파이프라인 전체를 책임진다. 어느 단계도 건너뛰지 않는다.

## 실행 순서

### 1단계 — 날짜 확인 (건너뛰기 금지)

```bash
date "+%Y-%m-%d %A %H:%M %Z"
```

이 출력에서 `YYYY-MM-DD`를 뽑아 파일명, 프론트매터 `date`, 알림 문구에 쓴다.
기억이나 추론으로 날짜를 대체하지 않는다.

### 2단계 — 주제 해석

- 사용자가 준 주제가 있으면 그것을 쓴다.
- 없으면 `topics/backlog.md`에서 `- [ ]` 로 시작하는 첫 항목을 고른다.
- 백로그가 비었으면 `posts/` 최근 5편을 읽고 겹치지 않는 주제를 스스로 정한다.
- **주제가 없다는 이유로 건너뛰지 않는다.**

주제를 백로그에서 골랐다면, 저장 성공 후 해당 줄을 `- [x]`로 바꾸고 뒤에 ` (YYYY-MM-DD)`를 붙인다.

### 3단계 — Thinker

주제를 넘긴다. 각도 후보 5개 이상과 선택된 1~2개를 받는다.

### 4단계 — Architect

Thinker의 선택 각도를 넘긴다. 문단 단위 흐름 설계를 받는다.

### 5단계 — Writer

Architect의 설계를 넘긴다. 초고를 받는다.

### 6단계 — Editor

초고를 넘긴다. 문체 위반·상투어·군더더기를 제거하고 분량을 맞춘 원고를 받는다.

### 7단계 — QA 루프

`QA_CHECKLIST.md` 전 항목을 판정시킨다.

- `FAIL` → 실패 항목을 붙여 Editor로 반송. **최대 3회.**
- `PASS` → 다음 단계로.
- 3회 반송 후에도 실패하면 남은 실패 항목을 하단 메모에 적고 저장한다.
  단 **2000자 초과만은 예외 없이 저장 금지**다. 통과할 때까지 Editor를 더 돌린다.

**QA 통과 전에는 절대 파일을 저장하지 않는다.** 초안을 posts/에 미리 쓰지 않는다.

### 8단계 — 저장

`posts/YYYY-MM-DD-슬러그.md` 로 저장한다. 슬러그는 제목에서 뽑은 짧은 로마자/한글 하이픈 표기.

```markdown
---
title: "글에서 가장 뾰족한 한 문장"
date: YYYY-MM-DD
slug: 슬러그
topic: "입력 주제"
chars: 1732
---

(본문)
```

저장 직후 실측하고 `chars`를 실제 값으로 맞춘다.

```bash
python3 scripts/count.py posts/YYYY-MM-DD-슬러그.md
```

### 9단계 — 알림

```bash
bash scripts/notify.sh "YYYY-MM-DD" "제목" "1732" "posts/YYYY-MM-DD-슬러그.md"
```

실행 결과를 확인한다. 실패하면 `NOTIFICATIONS.md`에 append 되었는지 직접 확인한다.

### 10단계 — 보고

글 전문과 **실측 글자 수**를 출력한다. 추정치를 출력하지 않는다.

## 누락 보충

세션 시작 시 `posts/`의 최신 날짜를 확인한다. 그 이후로 지나간 화/목/토/일 중
글이 없는 날짜가 있으면 **즉시** 보충 집필한다. 하루당 한 편씩, 오래된 날짜부터.
보충분의 `date`는 원래 예정일로 적고, 하단 메모에 실제 집필일을 남긴다.

## 금지

- "다음에 하겠다", "초안만 잡아두었다" 류의 응답
- 중간 승인 요청
- 단계 생략
- QA 미통과 저장
